# اختبارات SQL Server المستقلة

يشترط تشغيلها تحديد PENSIONMS_TEST_SQLSERVER باتصال خادم SQL Server للاختبار.
التجهيزات تستبدل اسم قاعدة البيانات باسم PensionMS_Test_ متبوعًا بـ GUID، وتنشئ
هذه القاعدة وحدها وتزيلها بعد الاختبارات. جميع البيانات مصطنعة. الاتصال لا يُقرأ
من appsettings ولا يُستخدم لاختبارات PensionMS.Tests الحالية.

يُنشأ المخطط من نموذج EF الفعلي. تُستثنى بيانات HasData الخاصة بـ RolePermissions
لأنها تشير إلى Permissions غير موجودة في التهيئة الحالية؛ تبقى قيود العلاقات كما هي.
هذه التجهيزات لا تثبت صحة بيانات الصلاحيات الأولية. تزرع الاختبارات أدوارها المطلوبة صراحةً.

عندما يكون API قيد التشغيل، أضف `--artifacts-path .artifacts/db-access` للبناء
والاختبار لتجنب الكتابة فوق ملفات التطبيق المستخدمة.

تشغيل المشروع صراحةً:

```powershell
dotnet test .\PensionMS.IntegrationTests\PensionMS.IntegrationTests.csproj --artifacts-path .artifacts/db-access --nologo
```

غياب المتغير أو عدم إمكانية الاتصال يفشل التشغيل؛ لا يُعرض نجاح دون إجراء تحقق SQL.
AuthorizationHttpSqlTests يشغّل Kestrel محليًا على منفذ عشوائي ويستخدم Controllers
وmiddleware وJWT وPermissionHandler الفعلية مع بيانات مصطنعة. يفحص عزل الفروع
والـcache ورفض النطاق المخالف في PDF/Excel وسحب صلاحية رمز الدخول بعد حذف المستخدم.
هذا مضيف اختبار بتسجيلات DI صريحة؛ لا يشغّل Program.cs أو Jobs أو اتصال التطبيق الفعلي.

اختبارات المعاملات تحقن فشلًا بعد الحفظ وتعيد القراءة بسياق جديد، وتختبر التزامن وقفل
التدقيق. ReadCounter يحصي قراءات قائمة الجرد وOutbox. اختبار الفهارس يستعمل 100,000
سجل تدقيق مصطنعًا، يقارن النتائج وSTATISTICS IO، ويكرر تطبيق السكربتات والتراجع عنها.
القياسات مصطنعة ولا تعادل Execution Plans أو اختبار حمل على الإنتاج.
